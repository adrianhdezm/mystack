# 01 - Routes and Layout

## Overview

The public layout and landing page are registered explicitly in `app/routes.ts` using the `layout()` and `index()` helpers. This is the only route registry — never use filename conventions or ad-hoc client routers.

The public layout wraps the landing page (and later, legal pages) in a shared shell that provides `SiteHeader` and `SiteFooter`. It is a sibling to the authenticated app layout — neither nests inside the other.

## Steps

### 1. Create the public layout route file

Create `app/routes/public-layout.tsx`.

```tsx
import { Outlet } from "react-router";
import { SiteFooter } from "~/components/landing/SiteFooter";
import { SiteHeader } from "~/components/landing/SiteHeader";
import type { Route } from "./+types/public-layout";

export default function PublicLayout(_props: Route.ComponentProps) {
  return (
    <div className="flex min-h-screen flex-col">
      <SiteHeader />
      <main className="flex-1">
        <Outlet />
      </main>
      <SiteFooter />
    </div>
  );
}
```

Do not add any authentication check or redirect here. This layout is intentionally public.

### 2. Create the landing page route file

Create `app/routes/home.tsx`.

```tsx
import type { Route } from "./+types/home";
import { CTASection } from "~/components/landing/CTASection";
import { Features } from "~/components/landing/Features";
import { Hero } from "~/components/landing/Hero";

export const meta: Route.MetaFunction = () => [{ title: "/* Product name */" }];

export default function HomePage(_props: Route.ComponentProps) {
  return (
    <>
      <Hero />
      <Features />
      <CTASection />
    </>
  );
}
```

No `loader` is needed unless the page displays dynamic data. Add a `loader` export only if the page needs server-rendered data.

### 3. Register both routes in `app/routes.ts`

Open `app/routes.ts` and add the public layout group. Merge it into the existing route array — do not replace routes that are already there.

```ts
import {
  index,
  layout,
  route,
  type RouteConfig,
} from "@react-router/dev/routes";

export default [
  layout("routes/public-layout.tsx", [
    index("routes/home.tsx"),
    // Legal pages will be added here by adding-legal-pages
  ]),
  // Existing auth and app routes are preserved below
  route("login", "routes/login.tsx"),
  route("signup", "routes/signup.tsx"),
  layout("routes/app-layout.tsx", [
    route("dashboard", "routes/dashboard.tsx"),
    // ... other authenticated routes
  ]),
  route("api/auth/*", "routes/auth.tsx"),
] satisfies RouteConfig;
```

Preserve every route already registered. Only add the `layout("routes/public-layout.tsx", [...])` block. If no `login`, `signup`, or app-layout routes exist yet (e.g., `simple` tier), the array may only contain the public layout group.

### 4. Create the component directory

Create `app/components/landing/` and add the five shell components. Populate them with the actual section content from [02-landing-page-sections.md](02-landing-page-sections.md):

- `app/components/landing/SiteHeader.tsx`
- `app/components/landing/SiteFooter.tsx`
- `app/components/landing/Hero.tsx`
- `app/components/landing/Features.tsx`
- `app/components/landing/CTASection.tsx`

### 5. Verify generated route types resolve

After updating `app/routes.ts`, the `./+types/public-layout` and `./+types/home` modules are generated by React Router. Run the typecheck command to confirm they resolve:

```sh
pnpm typecheck
```

If the generated types are missing, ensure the route files are correctly referenced in `app/routes.ts` — a path mismatch is the most common cause.

### 6. Verify the authenticated layout is unaffected

If the project already has an authenticated app layout (e.g., `app/routes/app-layout.tsx`), confirm it is a sibling `layout()` group in `app/routes.ts`, not nested inside the public layout. The two `layout()` blocks must be siblings at the top level of the route array.

## Expected Results

- `GET /` serves the landing page through the public layout with no authentication requirement.
- Authenticated app routes (if present) continue to require login.
- `./+types/public-layout` and `./+types/home` resolve in TypeScript.
- No existing route is changed or removed.
